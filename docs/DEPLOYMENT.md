# 部署说明

## 本机预览

1. 安装 Node.js 22.13.0 或更高版本，运行 `npm ci`。
2. 复制 `.dev.vars.example` 为 `.dev.vars`，按需填入自己的模型配置。
3. 运行 `npm run build`，生成 Worker 与本机绑定配置。
4. 运行 `npm run db:init`，按顺序应用 `drizzle/` 中的本机数据库迁移。
5. 运行 `npm run dev`，打开终端打印的地址。

本机数据库、文件和开发状态在忽略的 `.wrangler/`、`.sites-runtime/` 等目录中，不随源码发布。数据库初始化可重复执行，已应用的迁移会跳过。

## 使用 Sites 托管

1. 创建自己的 Sites 项目，把返回的项目 ID 设置到 `.openai/hosting.json` 的 `project_id`。仓库只保留 `DB`、`BUCKET` 绑定名称，不包含原站点的托管 ID。
2. 为该项目配置 D1 的 `DB`、R2 的 `BUCKET` 绑定，并应用 `drizzle/` 数据库迁移。
3. 在托管平台设置自己的运行时密钥和变量；生产 `AI_ALLOWED_EMAIL` 应填写空间主人账号，而非开发模拟账号。
4. 按平台要求构建、保存并部署。生产环境登录由平台注入受信任身份。

源码不携带生产数据库、原件、课程目录或运行时密钥。

## 部署到其他平台

需要 Worker 运行环境、D1 / R2 或对应存储适配，以及可信的服务端认证。

`app/chatgpt-auth.ts` 读取托管平台验证过的身份请求头。普通反向代理如果接受浏览器自行传入的这些头，会破坏账号隔离。迁移到其他平台时，必须替换为自己的登录和会话实现，再接入 API 身份检查。开发模拟登录只用于本机。

GitHub Pages 只适合静态资源，不能执行当前的同步、模型和归档 API。
